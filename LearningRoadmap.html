1.1 XAML 与代码分离
理解为什么 WPF 用 XML 写界面而不是 C#
▼

做什么学习 XAML 基本语法

XAML (Extensible Application Markup Language) 是 WPF 的声明式 UI 语言。你在 .xaml 文件中描述界面结构，在 .xaml.cs / .xaml.vb 中编写交互逻辑。

  • 学习元素声明：<StackPanel>、<Grid>、<Button> 等
  • 属性赋值：简单属性（Width="100"）vs 标记扩展（Binding、StaticResource）
  • 命名空间：xmlns、xmlns:x、自定义控件库引用
  • 代码后台：x:Name 在 C# 中生成字段，x:Class 指定 partial class

为什么这么做

WPF 的设计哲学是 关注点分离（Separation of Concerns）。UI 设计师负责 XAML，程序员负责 C# 逻辑。两者可以并行开发，互不干扰。Windows Forms 时代所有 UI 都写在 C# 代码里，界面一旦变化就要改代码、重新编译，效率极低。

好处

  • 热重载：修改 XAML 后无需重新编译，即时预览效果
  • 可读性：XAML 的树形结构天然对应 UI 层级，一目了然
  • 设计工具支持：Visual Studio 设计器、Blend for Visual Studio 都基于 XAML
  • 数据绑定：XAML 的 Binding 表达式让 UI 自动跟随数据变化

效果

在本项目中，GlassTextBox.xaml 定义了控件的视觉结构（Template + Style），GlassTextBox.cs 只处理逻辑（密码可见切换等）。这种分离让样式修改完全不需要动 C# 代码。

1.2 依赖属性 (DependencyProperty)
WPF 属性系统的核心——比普通 C# 属性强大得多
▼

做什么理解依赖属性的注册与使用

// 1. 注册依赖属性
public static readonly DependencyProperty InputPlaceholderProperty =
    DependencyProperty.Register(
        "InputPlaceholder",           // 属性名
        typeof(string),               // 属性类型
        typeof(GlassTextBox),         // 所有者类型
        new PropertyMetadata(string.Empty));  // 默认值

// 2. CLR 包装器（让 C# 代码也能用）
public string InputPlaceholder
{
    get => (string)GetValue(InputPlaceholderProperty);
    set => SetValue(InputPlaceholderProperty, value);
}

为什么这么做

普通 C# 属性没有这些能力：
  • 数据绑定：只有依赖属性才能作为 Binding 的源和目标
  • 动画：只有依赖属性才能被 StoryBoard / Animation 驱动
  • 样式 Setter：<Style> 只能设置依赖属性
  • 继承：可以通过 Inherits 让子控件自动继承父控件的属性值
  • 默认值：由 WPF 框架管理，节省内存——只有值改变时才占用存储

好处

  • 内存优化：默认值不存储在实例中，只在改变时分配内存
  • 变更通知：PropertyMetadata 中的回调函数自动通知 UI 更新
  • 优先级系统：Local Value > Style Trigger > Style Setter > Default —— 框架自动解析
  • 跨平台绑定：同一个依赖属性可以同时被动画、样式、绑定驱动

效果

本项目中每个控件都有 5-15 个依赖属性。例如 GlassTextBox 的 InputPlaceholder、InputLength、InputMin、InputMax、InputTitle 等。这些属性都是依赖属性，所以能在 XAML 中用 {Binding} 绑定、用 <Style> 设置默认值、用动画驱动视觉变化。

实操练习

  1. 在 Visual Studio 中创建一个 WPF 用户控件
  2. 注册一个 MyTextProperty 依赖属性（string 类型）
  3. 在 XAML 中用 Binding 绑定它
  4. 在 Style 中用 Setter 设置默认值
  5. 用 PropertyMetadata PropertyChangedCallback 打印变更日志

1.3 路由事件 (RoutedEvent)
WPF 事件系统的三大策略——事件如何在视觉树中传播
▼

做什么理解三种路由策略

策略方向说明典型例子
Tunnel (隧道)根 → 目标从视觉树根部向下穿透到目标元素PreviewKeyDown
Bubble (冒泡)目标 → 根从目标元素向上传播到根KeyDown、Click
Direct (直接)只在目标类似普通 .NET 事件，只在声明元素上触发MouseEnter
// 拦截键盘事件——冒泡到最外层容器
private void GlassKeyboard_KeyDown(object sender, KeyEventArgs e)
{
    if (e.Key == Key.Enter || e.Key == Key.Return)
    {
        e.Handled = true;  // 标记已处理，阻止继续冒泡
        HandleConfirm();
    }
}

为什么这么做

WPF 用路由事件解决了一个关键问题：事件委托的性能。在 WinForms 中，如果 100 个按钮各自注册 Click 事件，就是 100 个委托。而 WPF 的路由事件只注册一次处理函数，通过视觉树路由分发。更重要的是，你可以在外层容器上"拦截"子元素的事件——这就是为什么 GlassKeyboard 只在最外层注册 KeyDown，就能捕获所有子按钮的回车键。

好处

  • 事件聚合：一个处理函数管理所有子元素的同类事件
  • Preview 机制：Tunnel 策略让你在事件到达目标之前就拦截处理
  • 性能：减少事件订阅数量，降低内存占用
  • 灵活性：e.Handled = true 可以阻止事件继续传播

效果

本项目的 GlassKeyboard 在 OnApplyTemplate 中给 PopupOverlay 注册 KeyDown 事件。由于冒泡机制，所有子按钮的回车键都会被统一捕获处理——无需给每个按钮单独注册。

1.4 控件模板 (ControlTemplate)
控件的"外衣"——同一个逻辑可以有完全不同的视觉表现
▼

做什么掌握 ControlTemplate 的结构与生命周期

<ControlTemplate x:Key="GlassButtonTemplate" TargetType="Button">
    <Border x:Name="border" CornerRadius="14"
            Background="{TemplateBinding Background}"
            BorderBrush="{TemplateBinding BorderBrush}">
        <ContentPresenter HorizontalAlignment="Center"
                          VerticalAlignment="Center"/>
    </Border>
</ControlTemplate>

控件模板的关键概念：

  • 视觉树 (Visual Tree)：模板内的所有元素构成控件的视觉表现
  • 逻辑树 (Logical Tree)：模板外的控件层级——Button → StackPanel → Window
  • TemplateBinding：将模板内元素的属性绑定到宿主控件的属性
  • ContentPresenter：占位符，显示控件的 Content
  • TemplatePart (PART_ 命名)：约定命名，OnApplyTemplate 中通过 GetTemplateChild("PART_xxx") 获取

为什么这么做

控件模板是 WPF 实现 外观与行为分离 的核心机制。一个 Button 逻辑上永远是"可点击的"，但你可以用 ControlTemplate 把它变成圆形、方形、毛玻璃、金属拉丝——任何你能画出来的东西。这意味着：
  • 同一套逻辑代码，不同的视觉风格
  • 设计师可以只改 XAML 模板，不需要动 C# 代码
  • 可以通过 Style 批量替换所有按钮的外观

好处

  • 解耦：控件逻辑和视觉完全分离
  • 复用：一个 Template 可以应用给无数个控件实例
  • 主题：切换主题 = 替换所有 ControlTemplate
  • 自定义：完全重写控件外观，但保留原生行为

效果

本项目的 GlassTextBox.xaml 中定义了完整的控件模板：多层 Border（外框 + 内框 + 渐变），水印 TextBlock（用 Style+DataTrigger 控制显示），以及 ContentPresenter 占位符。这让你看到的毛玻璃输入框本质上还是一个标准 TextBox，只是"穿了件新衣服"。

OnApplyTemplate 生命周期：这个方法在控件模板被应用时调用。在这里通过 GetTemplateChild("PART_xxx") 获取模板内的子元素引用，并注册事件处理。对于复合控件（如本项目的 GlassKeyboard），OnApplyTemplate 还负责创建动态子元素（BuildNumericKeys 等）。

2.1 Style 与 Setter
批量设置控件属性——隐式样式 vs 显式样式
▼

做什么掌握两种样式类型

<!-- 显式样式：需要手动引用 -->
<Style x:Key="MyButtonStyle" TargetType="Button">
    <Setter Property="Background" Value="#4FB6FF"/>
    <Setter Property="Foreground" Value="White"/>
</Style>

<!-- 隐式样式：自动应用于所有同类型控件 -->
<Style TargetType="TextBox">
    <Setter Property="FontFamily" Value="Segoe UI"/>
</Style>

<!-- 样式继承 -->
<Style x:Key="SpecialButton" BasedOn="{StaticResource MyButtonStyle}">
    <Setter Property="FontSize" Value="18"/>
</Style>

为什么这么做

如果没有 Style，你需要给每个控件逐一设置属性——10 个按钮就要写 10 遍相同的属性。Style 本质上就是属性值的"模板"，一处定义，多处复用。BasedOn 继承机制让你可以创建层级化的样式系统：基础样式 → 变体样式 → 特殊样式。

好处

  • DRY 原则：属性值只定义一次
  • 主题切换：更换 Style 即可批量改变所有控件外观
  • 继承：BasedOn 让样式可以层层叠加

效果

本项目的 GlassTextBox.xaml 中的 Style 定义了默认背景色、边框色、字体等。所有使用该样式的文本框自动获得一致的毛玻璃外观。

2.2 Trigger 与 DataTrigger
属性变化自动驱动视觉变化——无需写一行 C# 代码
▼

做什么理解三种触发器及优先级

<!-- PropertyTrigger：属性值变化时触发 -->
<Style.Triggers>
    <Trigger Property="IsMouseOver" Value="True">
        <Setter Property="Opacity" Value="0.8"/>
    </Trigger>
</Style.Triggers>

<!-- DataTrigger：绑定表达式结果变化时触发 -->
<DataTrigger Binding="{Binding Text.Length}" Value="0">
    <Setter Property="Visibility" Value="Visible"/> <!-- 显示水印 -->
</DataTrigger>
<DataTrigger Binding="{Binding Text.Length}" Value="1">
    <Setter Property="Visibility" Value="Collapsed"/> <!-- 隐藏水印 -->
</DataTrigger>

<!-- 多条件触发器 -->
<MultiTrigger>
    <MultiTrigger.Conditions>
        <Condition Property="IsMouseOver" Value="True"/>
        <Condition Property="IsPressed" Value="True"/>
    </MultiTrigger.Conditions>
    <Setter Property="Opacity" Value="0.5"/>
</MultiTrigger>

为什么这么做

WPF 属性优先级系统（从高到低）：
  1. Local Value（代码中直接设置）
  2. Template Trigger（ControlTemplate 中的 Trigger）
  3. Style Trigger（Style 中的 Trigger）
  4. Style Setter（Style 中的 Setter）
  5. Inherited Value（继承自父控件）
  6. Default Value（依赖属性注册时的默认值）
理解这个优先级至关重要！它决定了当多个来源设置同一个属性时，哪个值最终生效。

好处

  • 零代码：纯 XAML 实现所有视觉状态变化
  • 性能：WPF 框架内部优化，比手动监听属性变更更高效
  • 声明式：设计工具可以预览和编辑触发器效果

效果

本项目的核心交互模式就是 DataTrigger。例如 GlassTextBox 的水印：当 Text.Length == 0 时显示，否则隐藏。GlassKeyboard 的按键高亮：当 IsChecked == True 时背景变深。所有这些都是纯 XAML 实现。

2.3 TemplateBinding vs Binding
模板内绑定的两种方式——性能 vs 功能的权衡
▼

做什么区分两种模板绑定

<!-- TemplateBinding：单向、性能高 -->
<Border Background="{TemplateBinding Background}"/>

<!-- Binding：双向、功能全 -->
<Border Background="{Binding RelativeSource={RelativeSource TemplatedParent},
                     Path=Background}"/>
特性TemplateBindingBinding (RelativeSource)
方向仅单向 (控件→模板)双向均可
性能更高（编译时优化）略低（运行时解析）
Converter不支持支持
模式OneWay 固定可设置 Mode

为什么这么做

大部分模板内绑定都是单向的（从控件属性到视觉元素），用 TemplateBinding 性能最优。但当你需要 Converter、双向绑定、或更复杂的绑定表达式时，必须用 Binding RelativeSource={RelativeSource TemplatedParent}。本项目中大量使用 TemplateBinding，因为模板元素只需要读取控件属性值。

好处

  • TemplateBinding：编译时检查，性能最佳，代码最简洁
  • Binding TemplatedParent：功能完整，支持 Converter 和双向绑定

效果

本项目的毛玻璃边框色、背景透明度等都通过 TemplateBinding 绑定到控件属性，保证了模板渲染的高性能。

2.4 附加属性 (AttachedProperty)
让任何控件获得额外能力——本项目的 ShowKeyboard 和 Placeholder 都用到了
▼

做什么掌握 RegisterAttached 的注册与使用

// 注册附加属性
public static readonly DependencyProperty ShowKeyboardProperty =
    DependencyProperty.RegisterAttached(
        "ShowKeyboard",         // 属性名
        typeof(bool),           // 类型
        typeof(GlassKeyboard),  // 宿主类型
        new PropertyMetadata(false, OnShowKeyboardChanged));

// Getter/Setter（必须是 static）
public static bool GetShowKeyboard(DependencyObject obj) =>
    (bool)obj.GetValue(ShowKeyboardProperty);
public static void SetShowKeyboard(DependencyObject obj, bool value) =>
    obj.SetValue(ShowKeyboardProperty, value);

// 变更回调——附加属性的核心价值
private static void OnShowKeyboardChanged(DependencyObject d, DependencyPropertyChangedEventArgs e)
{
    if (d is TextBox textBox && e.NewValue is true)
    {
        textBox.Loaded += OnTextBoxLoaded;  // 绑定事件
    }
}

为什么这么做

附加属性的本质是：在不修改目标类的情况下，给任意控件注入新行为。TextBox 本身不知道键盘的存在，但通过附加属性 GlassKeyboard.ShowKeyboard="True"，你可以在 TextBox 加载时自动创建弹出键盘——而不需要继承 TextBox 创建一个新类。这就是"组合优于继承"的 WPF 实现。

好处

  • 零侵入：不需要修改 TextBox 源码或创建子类
  • 复用：同一个附加属性可以附加到任何控件上
  • XAML 友好：在 XAML 中用语法 local:ShowKeyboard="True" 使用
  • 自动发现：通过 FindChildByName 在视觉树中自动查找关联控件

效果

本项目的使用方式极其简洁：在任何 TextBox 上加一行 local:GlassKeyboard.ShowKeyboard="True"，就自动获得数字键盘支持。附加属性的变更回调在 TextBox 加载时触发，自动在视觉树中找到关联的 GlassKeyboardPopup 并注入键盘。

Register vs RegisterAttached：普通的 Register 用于控件自己的属性，只能在该控件上使用。RegisterAttached 注册的属性可以附加到任何 DependencyObject 上——这就是两者的根本区别。

3.1 GlassTextBox 毛玻璃文本框
本项目最核心的控件——理解多层 Border + 水印实现
▼

做什么分析 GlassTextBox 的模板结构

模板层次从外到内：

  1. 外框 Border：圆角 14px，渐变背景 #E0202020 → #1AFFFFFF，白色半透明边框 #33FFFFFF
  2. 内框 Border：圆角 11px，更暗的渐变 #E0101010 → #0AFFFFFF
  3. 水印 TextBlock：通过 Style+DataTrigger 绑定 Text.Length
  4. ContentPresenter：实际的 TextBox 内容区域
<!-- 水印实现核心 -->
<Style x:Key="PlaceholderStyle" TargetType="TextBlock">
    <Setter Property="Visibility" Value="Collapsed"/>
    <Style.Triggers>
        <DataTrigger Binding="{Binding Text.Length,
            RelativeSource={RelativeSource AncestorType=TextBox}}" Value="0">
            <Setter Property="Visibility" Value="Visible"/>
        </DataTrigger>
    </Style.Triggers>
</Style>

为什么这么做

  • 多层 Border：单层 Border 无法实现内外框不同的透明度效果。两层 Border 叠加产生深度感——外层稍亮，内层更暗，模拟毛玻璃的光折射效果
  • DataTrigger 绑定 Text.Length：TextBox 的 Text 是依赖属性，但其 Length 不是。通过 DataTrigger 监听 Length 变化，实现了水印的自动显示/隐藏
  • Style Setter：水印的 Visibility 默认设为 Collapsed（隐藏），只有 Text 为空时才显示——这是典型的"默认隐藏，条件显示"模式

好处

  • 视觉层次丰富，毛玻璃效果逼真
  • 水印实现零 C# 代码，纯 XAML 声明式
  • 通过依赖属性暴露 InputPlaceholder，用户完全可配置

效果

运行时看到的是一个双层圆角毛玻璃输入框，输入文字后水印自动消失，焦点时边框高亮——所有视觉变化都通过 Style + DataTrigger 驱动，不需要一行 C# 代码。

3.2 GlassPasswordBox 密码框
为什么用附加属性而不是继承 PasswordBox
▼

做什么理解 PasswordBox 的特殊性

PasswordBox 是 sealed 类——不能被继承。同时它的 Password 属性不是依赖属性，无法被绑定。这是 WPF 的安全设计（防止密码被绑定到日志、MVVM 框架等）。

本项目的解决方案：

  • 通过附加属性 GlassKeyboard.ShowKeyboard 赋予密码框键盘支持
  • 通过附加属性 GlassKeyboard.InputTitle/GlassKeyboard.ShowPasswordVisible 配置键盘选项
  • 密码可见切换通过 PasswordBoxTemplate 中的 DataTrigger 实现

为什么这么做

由于 PasswordBox.Sealed，你无法继承它创建 GlassPasswordBox : PasswordBox。所以项目采用了组合模式：在 GlassKeyboardPopup 内部创建 PasswordBox，通过附加属性在运行时注入键盘行为。这比继承更灵活——附加属性可以附加到任意控件。

好处

  • 绕过 sealed 限制，无需使用继承
  • 密码框获得与文本框一致的键盘体验
  • 密码可见/隐藏切换完全通过模板样式实现

效果

用户看到的密码框与文本框外观一致（毛玻璃边框、水印提示），但内部使用的是原生 PasswordBox 保证安全性。

3.3 GlassButton / GlassToggleButton
按钮类控件的模板与触发器实战
▼

做什么理解按钮模板的交互状态

按钮有四个状态，每个状态对应不同的视觉表现：

状态触发条件视觉效果
Normal默认半透明背景，渐变边框
HoverIsMouseOver=TrueOpacity 降低，鼠标悬停反馈
PressedIsPressed=TrueOpacity 更低，点击反馈
CheckedIsChecked=True（ToggleButton）背景色加深
<ControlTemplate TargetType="Button">
    <Border x:Name="border" CornerRadius="14"
            Opacity="1"
            Background="{TemplateBinding Background}">
        <Border.Triggers>
            <EventTrigger RoutedEvent="MouseEnter">
                <BeginStoryboard>
                    <Storyboard>
                        <DoubleAnimation Storyboard.TargetName="border"
                            Storyboard.TargetProperty="Opacity"
                            To="0.8" Duration="0:0:0.2"/>
                    </Storyboard>
                </BeginStoryboard>
            </EventTrigger>
        </Border.Triggers>
        <ContentPresenter/>
    </Border>
</ControlTemplate>

为什么这么做

按钮模板中的状态变化是用户交互反馈的关键。没有视觉反馈的按钮会让用户感到"卡顿"或"无响应"。通过 ControlTemplate 中的 Trigger 和 EventTrigger + Storyboard，你可以实现平滑的过渡动画，让用户明确知道"我点击到了"。

好处

  • 按钮视觉完全自定义，不受系统样式限制
  • 交互反馈通过动画实现，用户体验流畅
  • ToggleButton 的选中状态自动切换，无需额外代码

效果

按钮按下时平滑变暗，松开时恢复——这是通过 Storyboard 动画驱动的依赖属性变化。整个过程零 C# 代码。

3.4 GlassCard 毛玻璃卡片
分层架构——高光层 + 内容层的叠加设计
▼

做什么理解 GlassCard 的双层架构

GlassCard 的模板由三层组成：

  1. 外框 Border：圆角 18px，渐变背景，白色边框 —— 整体容器
  2. 高光 Border（IsElevated=True 时）：从上到下 30% 高度的半透明渐变 —— 模拟光照效果
  3. ContentPresenter：实际内容

为什么这么做

  • 内容灵活：ContentPresenter 可以放任何内容
  • 性能：纯 XAML 实现，不依赖图片资源

效果

打开 MainWindow.xaml 可以看到，所有键盘和弹窗都包裹在 GlassCard 中——卡片效果统一，有层次感，有阴影深度。

4.1 GlassKeyboard 附加属性系统
触发入口——TextBox.Loaded → 附加属性回调 → 注入键盘
▼

做什么理解从附加属性到键盘注入的完整链路

  1. 用户在 XAML 中写 local:GlassKeyboard.ShowKeyboard="True"
  2. 附加属性 OnShowKeyboardChanged 回调触发
  3. 回调中给 TextBox 注册 Loaded 事件
  4. TextBox 加载时，OnTextBoxLoaded 通过 FindChildByName 在视觉树中查找 GlassKeyboardPopup
  5. 找到后调用 kbpopup.BindToTextBox(textBox)
// FindChildByName — 视觉树遍历查找
private static T FindChildByName<T>(DependencyObject parent, string name)
    where T : FrameworkElement
{
    int count = VisualTreeHelper.GetChildrenCount(parent);
    for (int i = 0; i < count; i++)
    {
        var child = VisualTreeHelper.GetChild(parent, i);
        if (child is T element && element.Name == name)
            return element;
        var result = FindChildByName<T>(child, name);  // 递归
        if (result != null) return result;
    }
    return null;
}

为什么这么做

这个设计的核心是解耦。TextBox 不需要知道键盘的存在，键盘也不需要知道谁触发了它。附加属性充当"桥梁"——它监听 TextBox 的生命周期（Loaded），然后在视觉树中自动搜索匹配的键盘控件。这意味着你可以在同一个 XAML 中放置多个 TextBox 和多个 GlassKeyboardPopup，它们通过名称自动配对。

好处

  • TextBox 和键盘完全解耦
  • 通过名称自动配对，无需手动编码关联
  • 一个键盘可以服务多个 TextBox

效果

用户只需在 TextBox 上加一行附加属性，键盘功能就自动可用。开发者不需要写任何事件处理代码。

4.5 输入验证与确认

▼

做什么理解输入验证的完整逻辑

private void HandleConfirm()
{
    // 1. 前导零处理
    var trimmedText = StripLeadingZeros(currentInput);

    // 2. 小数点处理——确保不以小数点结尾
    if (trimmedText.EndsWith("."))
        trimmedText = trimmedText.TrimEnd('.');

    // 3. 范围验证
    if (IsNumeric && double.TryParse(trimmedText, NumberStyles.Any,
        CultureInfo.InvariantCulture, out double val))
    {
        if (val < InputMin) val = InputMin;
        if (val > InputMax) val = InputMax;
        trimmedText = val.ToString(CultureInfo.InvariantCulture);
    }

    // 4. 更新到目标 TextBox
    targetTextBox.Text = trimmedText;
}

为什么这么做

用户在键盘上随意输入可能产生非法值（前导零 "007"、空小数点 "3."、超出范围的值）。在确认时统一验证和清洗，既保证了数据完整性，又不会在每次按键时打断用户输入。这是一种"宽容输入，严格确认"的设计模式。

好处

  • 用户体验友好：输入过程中不打断
  • 数据完整性：确认时自动修正和验证
  • 范围保护：超出 min/max 自动钳制

效果

用户输入 "007" 确认后变成 "7"，输入 "3." 确认后变成 "3"，输入 "-5" 但 min=0 时自动变成 "0"。

var overlay = new Window()
{
    WindowStyle = WindowStyle.None,      // 无标题栏/边框
    AllowsTransparency = true,           // 允许透明

6.1 FishEye 鱼眼效果
距离检测 + 缩放动画——鼠标靠近时按钮放大的交互效果
▼

做什么理解鱼眼效果的算法

FishEye 效果的核心流程：

  1. 距离检测：鼠标移动时，计算鼠标位置与每个按钮中心点的距离
  2. 缩放计算：距离越近缩放越大，最大 ScaleFactor（默认 1.35），超出范围的为 1.0
  3. 动画驱动：使用 CubicEase 缓动函数实现平滑缩放
  4. Transform 分组：ScaleTransform（缩放）+ TranslateTransform（位移补偿）
// 核心算法
double dist = Math.Sqrt(Math.Pow(mousePos.X - center.X, 2) +
                        Math.Pow(mousePos.Y - center.Y, 2));
double scale = 1.0;
if (dist < Range)
{
    // 线性映射：距离越近缩放越大
    double t = 1.0 - (dist / Range);
    scale = 1.0 + (ScaleFactor - 1.0) * t;
}

// 动画驱动
var animation = new DoubleAnimation(scale,
    TimeSpan.FromSeconds(0.15)) { EasingFunction = new CubicEase() };
scaleTransform.BeginAnimation(ScaleTransform.ScaleXProperty, animation);
scaleTransform.BeginAnimation(ScaleTransform.ScaleYProperty, animation);

为什么这么做

鱼眼效果的核心价值是视觉引导。在密集的按钮排列中，用户可能难以找到目标。当鼠标靠近时按钮放大，提供了即时的视觉反馈，帮助用户确认"我正在指向正确的按钮"。这在工具栏、导航菜单等场景中非常有效。

好处

  • 视觉引导：鼠标靠近时按钮放大，帮助用户确认目标
  • 交互趣味性：比静态按钮更有趣，提升用户体验
  • 性能：基于 Transform 的动画性能极高，不影响布局
  • 自定义：ScaleFactor 和 Range 都可配置

效果

在数字键盘上移动鼠标，靠近的按钮平滑放大，远离后恢复——所有动画使用 CubicEase 缓动，过渡自然流畅。

Transform 分组的必要性

如果不使用 TranslateTransform，缩放时按钮会向左上角偏移（因为默认缩放原点是左上角 0,0）。通过 TranslateTransform 补偿偏移量，让按钮在原位缩放。这就是为什么需要 TransformGroup 而不是单独的 ScaleTransform。

6.2 水印 Placeholder 实现
Style Setter vs Local Value 的优先级博弈
▼

做什么理解水印的完整实现机制

水印通过两层机制实现：

  1. Style + DataTrigger：TextBlock 的 Visibility 由 Text.Length 决定
  2. 附加属性 InputPlaceholder：传递水印文本内容

为什么这么做

这里有一个精妙的设计决策：水印 TextBlock 的 Visibility 放在 Style.Setter 中而不是作为 Local Value。原因是 WPF 属性优先级：Local Value > Style Setter。如果 Visibility 是 Local Value，DataTrigger 的 Setter 就无法覆盖它。通过将默认值放在 Style Setter 中，DataTrigger 的 Setter 可以在条件满足时成功修改 Visibility。

好处

  • 水印显示/隐藏完全自动化
  • 优先级正确——DataTrigger 能够控制 Visibility
  • 零 C# 代码，纯 XAML 声明式

效果

输入框为空时显示灰色水印文字，输入任意字符后水印立即隐藏——这个过程完全由 DataTrigger 自动驱动。

6.4 性能与优化
FrameworkElementFactory vs XAML、密封集合问题——实战中的坑与解
▼

做什么理解程序化创建 UI 的性能考量

FrameworkElementFactory vs XAML

方式优势劣势
XAML可读性高、设计器支持、编译时检查编译时确定，无法动态调整
FrameworkElementFactory运行时动态创建、参数化布局代码冗长、无设计器支持

密封集合 (Sealed Collection) 问题

常见错误：ItemsSource 绑定到一个集合后，该集合会被 WPF 内部密封。之后尝试调用 Add()、Clear() 等方法会抛出 InvalidOperationException。

解决方案：在修改集合前检查 IsSealed，或者创建新集合赋值给 ItemsSource。

为什么这么做

本项目的键盘控件（GlassKeyboard、GlassKeyboardPopup）使用 FrameworkElementFactory 动态创建按钮。这是因为键盘布局需要根据参数（按钮数量、类型、排列方式）在运行时调整。虽然 XAML 更优雅，但无法满足这种动态需求。

好处

  • 动态布局完全参数化
  • 一个代码路径支持多种键盘类型
  • 避免了密封集合异常

效果

数字键盘和字母键盘共享同一套创建逻辑，通过参数控制差异——代码复用率高，维护成本低。

性能优化技巧

  • 虚拟化：ListBox/TreeView 默认启用虚拟化，只渲染可见项
  • 冻结：Freeze() 冻结 Brush 等资源，减少内存开销
  • 缓存：重复使用的 ControlTemplate 应该定义在 Resources 中复用
  • 延迟加载：复杂控件可以延迟到需要时再创建

推荐学习顺序

  1. 先学 XAML 基础（阶段一）—— 这是一切的基础
  2. 再学依赖属性—— WPF 属性系统的核心，后面每个控件都用到
  3. 然后学 ControlTemplate—— 理解"控件 = 逻辑 + 模板"的设计哲学
  4. 接着学 Style + Trigger—— 本项目视觉效果的实现手段
  5. 最后学附加属性—— 本项目的"粘合剂"，连接独立控件

实操建议

  • 边学边改：每个概念学完后，修改本项目的对应代码观察效果
  • 从简单开始：先改 GlassButton 的颜色，再改 GlassTextBox 的模板，最后挑战 GlassKeyboard
  • 善用调试：在 Visual Studio 中用"Live Visual Tree"查看运行时的控件层级
  • 记录笔记：把遇到的坑和解决方案记下来——比如密封集合问题、TemplateBinding 方向问题

常见陷阱

  • TemplateBinding 是单向的：模板内修改属性不会反映到控件上
  • Local Value 优先级最高：Style Setter 无法覆盖 Local Value
  • FrameworkElementFactory 已过时：推荐用 FrameworkElementFactory 的替代方案 XamlReader
  • ItemsSource 绑定后集合被密封：不能直接修改，需要创建新集合
